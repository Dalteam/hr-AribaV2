# تشغيل الميزات الجديدة (المراحل 1–7)

## 1) ملفات SQL — شغّلها بالترتيب في Supabase › SQL Editor
| الملف | المحتوى |
|---|---|
| `sql/10_phase1_workflow_upgrade.sql` | إجازة بدون راتب، راتب مقدم، مهلة المدير/التصعيد، رفض بسبب، إرجاع للمدير، صلاحيات المديرين، تفويض المدير، التقديم بالنيابة، تغيير الآيبان، تعديل البيانات، رفع المستندات، **إيميل تلقائي لكل إشعار**، وجدولة pg_cron |
| `sql/11_phase5_candidates.sql` | نموذج التوظيف العام + المرشحون + القبول/الرفض |
| `sql/12_phase6_goals.sql` | المستهدفات والتقييم (سنوي/ربع سنوي/شهري) |

> الملفات آمنة لإعادة التشغيل (`create or replace` / `if not exists`). اختُبرت على Postgres 16 محلياً بسيناريوهات في `sql/tests/`.

## 2) الإيميل التلقائي (إشعارات + تقارير)
1. فعّل **pg_net** و**pg_cron** من Database › Extensions (ثم أعد تشغيل ملف 10 إن لم تكن مفعّلة).
2. انشر الدالتين من `supabase/functions/`:
   - `ariba-notify-dispatch` (verify_jwt = false) — يرسل إيميل لكل إشعار جديد.
   - `ariba-send-report` (verify_jwt = true) — يرسل التقارير للمستلمين المختارين.
3. أسرار الدوال (Edge Functions › Secrets): `RESEND_API_KEY` ، `EMAIL_FROM` ، `NOTIFY_SECRET`.
4. قيمة `NOTIFY_SECRET` = نتيجة: `select value from ariba_security_flags where key='notify_secret';`
5. اضبط رابط الدالة مرة واحدة:
   `insert into ariba_security_flags(key,value) values('notify_url','https://<PROJECT_REF>.supabase.co/functions/v1/ariba-notify-dispatch') on conflict (key) do update set value=excluded.value;`
6. إيميل الموظف يُؤخذ من حقل البريد في ملفه؛ من لا إيميل له يصله الإشعار داخل التطبيق فقط.

## 3) الإعدادات داخل البرنامج
- **الإعدادات › تطبيق الموظف › سير الطلبات والمهل**: مهلة المدير المباشر والرئيس التنفيذي (أيام)، سقف الراتب المقدم، إيميلات إضافية للموارد البشرية.
- **الإعدادات › المستخدمون والصلاحيات › صلاحيات المديرين المباشرين**: ما يراه كل مدير من فريقه فقط (بيانات، إجازات، طلبات، حضور، رواتب، مستهدفات، تقييم، التقديم بالنيابة).
- **الإعدادات › الحضور › جدول الدوام (رسمي + رمضان)**: يتبدّل تلقائياً مع دخول رمضان (التقويم الهجري) أو بتواريخ يدوية؛ ساعات اليوم = مجموع كل فترات الدخول/الخروج.

## 4) الصفحات الجديدة
- **المرشحون**: رابط نموذج التقديم (`apply.html?k=…`) + لصق رابط/رمز مرشح لسحب بياناته وملفاته + قبول (يُضاف كموظف برقم تالٍ ويُنقل ملفاته لوثائقه) أو رفض.
- **المستهدفات** و**التقييم**: لـ HR / الرئيس التنفيذي / رئيس المجلس؛ والمدير المباشر من تطبيق الموظف (تبويب فريقي).
- **التقارير › منشئ التقارير المخصص** + زر «تصدير الصفحة» في رأس أي صفحة: Excel / PDF / Word + إرسال بالإيميل تلقائياً.

## 5) تطبيق الموظف
تبويبات: الإجازات (بدون راتب، راتب مقدم، تفويض المدير)، ملفي (رفع مستند، طلب تعديل بيانات، طلب تغيير الآيبان بخطاب موقّع)، أهدافي وتقييمي، فريقي (للمدير: بيانات الفريق حسب الصلاحيات، التقديم بالنيابة، المستهدفات، التقييم).

## 6) ملاحظات
- صور الورق الرسمي: ضع `head.png` و`foot.png` في `src/assets/letterhead/` ثم أعد البناء (تظهر في خطاب الآيبان والمطبوعات).
- لم يُنفَّذ بعد: خصم الإجازة بدون راتب والراتب المقدم تلقائياً من مسير الرواتب (الطلبات تُعتمد وتُسجَّل، والخصم يدوي حالياً).
- نوع `unpaid` في «طلب جديد» من HR يعتمد على قبول الدالة الحالية `ariba_hr_record_leave` لهذا النوع؛ إن رفضته أخبرني لأضيف دعمه.
- قائمة «وثائقي» في تطبيق الموظف تقرأ من الدالة الحالية؛ المستندات المعتمدة تُدرج في `ariba_documents` بنفس الصيغة المعتادة.

## المرحلة 8 — الموافقة بالتوقيع على المستندات
1. شغّل `sql/13_signed_documents.sql` (بعد ملف 10).
2. الإعدادات ← «توقيع المدير المباشر على المستندات»: حدّد أنواع المستندات التي يجب أن يوقّعها المدير المباشر.
3. الموظف: تبويب المستندات ← «أضف توقيعي» (رسم أو رفع صورة؛ يُحفظ في التطبيق/المتصفح فقط) ← «موافق مع التوقيع».
   - التوقيع يُدمج تلقائياً في مكان توقيع الموظف بالمستند (أو في خانة بنهاية المستند للمستندات القديمة).
   - بدون توقيع مدير: تُنفَّذ الموافقة المعتادة `ariba_employee_ack_template` فيصل المستند للموارد البشرية.
   - مع توقيع مدير: يقف عند المديـر (تبويب الموافقات ← «مستندات بانتظار توقيعي كمدير») ثم يذهب للموارد البشرية.
4. **افتراض يلزم مراجعته:** الدالة `ariba_sign_forward` تحدّث `workflow_requests.current_stage` إلى `hr` بعد توقيع المدير، وتطبيق الموظف يُكمل `ariba_employee_ack_template` تلقائياً عند فتح تبويب المستندات. إن كان جدول طلبات القوالب عندك مختلفاً عدّل هذه الدالة فقط.
5. الخصوصية: صورة التوقيع لا تُرسل ولا تُخزَّن بأي جدول؛ الموارد البشرية تستلم المستند الموقّع فقط.

## المرحلة 9 — مرفقات الإجازات على السيرفر
- شغّل `sql/14_leave_files.sql` في Supabase SQL Editor (بعد 10–13).
- مرفقات «طلب جديد» في تبويب الإجازات تُحفظ الآن في جدول `ariba_leave_files` على السيرفر فقط، وتظهر في «أرشيف مرفقات الطلبات» لكل مستخدم عنده صلاحية `requests`/`leaves` ومن أي جهاز.
- الموظف يرى مرفقات طلباته هو فقط (الدالة `ariba_leave_file_list/get`).
- مرفقات كانت محفوظة محليًا على جهاز قديم تُرحَّل تلقائيًا للسيرفر عند أول فتح لشاشة «كل الطلبات» على ذلك الجهاز.
- حذف الإجازة يحذف مرفقاتها.

## إرسال المستندات والإشعارات بالإيميل (ariba-send-email / ariba-notify-email)
البرنامج بينادي دالتين على Supabase لازم يتنشروا مرة واحدة (من غيرهم زر "إرسال إيميل للموظف" بيحوّل لـ Outlook):
```
supabase link --project-ref iwviydmapqpqihcdazpe
supabase functions deploy ariba-send-email --no-verify-jwt
supabase functions deploy ariba-notify-email --no-verify-jwt
```
- بيرسلوا من البريد المحفوظ في **الإعدادات ← البريد والإشعارات** (بريدي أنا، ولو مش موجود بريد الشركة).
- **مهم:** سيرفر Supabase يمنع الاتصال على المنفذين 25 و587. بريد **Microsoft 365 / Outlook** لا يعمل إلا على 587، فمش هينفع يتبعت منه مباشرة.
  الحل: حساب **Resend** (مجاني حتى 3000 رسالة/شهر) بعد توثيق دومين الشركة، ثم في Edge Functions › Secrets:
  `RESEND_API_KEY` و `EMAIL_FROM` (مثال: `Ariba HR <hr@ariba.com.sa>`) — والرد بيرجع لبريد المسؤول (reply-to).
  أو استخدم بريد يدعم منفذ 465 (Gmail بكلمة مرور تطبيق).
- لو الإرسال التلقائي مش متاح لأي سبب، البرنامج بيحمّل المستند ويفتح Outlook تلقائياً بدل رسالة "Failed to fetch".

## ربط رصيد الإجازة بين برنامج الموارد وتطبيق الموظف (sql/19)
1. شغّل `sql/19_leave_snapshot.sql` مرة واحدة في Supabase › SQL Editor.
2. افتح برنامج الموارد ← الإجازات ← الأرصدة: الشريط الأخضر «تطبيق الموظف بيعرض نفس الأرصدة دي بالظبط» معناه إن الربط شغال.
- برنامج الموارد بيحسب كل الأرصدة بالطريقة المختارة في الإعدادات ويكتبها في `ariba_leave_snapshots` (تلقائياً كل دقيقة طول ما البرنامج مفتوح، وفوراً بعد أي تغيير، أو بزر «مزامنة الآن»).
- تطبيق الموظف (رصيدي + فريقي للمدير) بيقرا نفس الرقم من الجدول، ويكمّل الاستحقاق من تاريخ الحساب لحد النهارده بنفس المعادلة.

## روابط تقديم لمرة واحدة للمرشحين (sql/20)
1. شغّل `sql/20_candidate_invites.sql` مرة واحدة في Supabase › SQL Editor (بعد ملف 11).
2. المرشحون ← «روابط تقديم لمرة واحدة» ← «إنشاء رابط جديد» لكل مرشح (بيتنسخ تلقائياً + زر واتساب).
3. لقفل الرابط العام: الإعدادات ← المستخدمون والصلاحيات والأمان ← «حماية نموذج التوظيف».

## نشر دالة الإرسال من لوحة Supabase (بدون أوامر)
Edge Functions › Deploy a new function › Via Editor ← الاسم `ariba-send-email` ← الصق محتوى `supabase/dashboard/ariba-send-email.ts` ← Deploy.
بعدها من إعدادات الدالة اقفل **Enforce JWT verification**. (نفس الخطوات لـ `ariba-notify-email` لو عايز إيميلات الإشعارات.)
Gmail: الخادم `smtp.gmail.com` والمنفذ `465` (البرنامج بيصحح 587 تلقائياً) وكلمة المرور = **App Password** من حساب Google (لازم التحقق بخطوتين مفعّل).
